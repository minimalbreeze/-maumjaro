# AI 서프라이즈 — 자동 콘텐츠 제작 시스템

실제로 있었던 이상한 이야기를 찾아 심사하고, 유튜브 영상 대본까지 만듭니다.

**지금은 Phase 2입니다.** 소재 수집 · 심사 · 대본 · 장면 분할 · 화면 프롬프트까지 됩니다.
이미지·영상 생성, 나레이션, 편집, 업로드는 아직 없습니다.

# 🟢 쉬운 방법 — GitHub에서 버튼 누르기 (권장)

PC에 아무것도 설치하지 않습니다. 브라우저만 있으면 됩니다.
스포츠 뉴스 도구와 똑같은 방식입니다.

## 처음 한 번만 — 비밀값 1개 등록

GitHub 리포 → **Settings** → 왼쪽 **Secrets and variables** → **Actions**
→ **New repository secret**

| Name (그대로 입력) | Secret (값) |
|---|---|
| `ANTHROPIC_API_KEY` | https://console.anthropic.com 에서 발급한 키 |

> 스포츠 뉴스 도구에서 이미 등록하셨다면 **그대로 쓰면 됩니다.** 다시 넣을 필요 없습니다.

## 실행하기

1. GitHub 리포 → 위쪽 **Actions** 탭
2. 왼쪽 목록에서 **"AI 서프라이즈 소재·대본 만들기"** 클릭
3. 오른쪽 **Run workflow** 버튼 클릭
4. 항목을 고르고 초록 **Run workflow** 누르기

| 항목 | 설명 |
|---|---|
| 무엇을 할까요 | **테스트만**(기본) = 돈 안 듦 / **소재만 찾기** / **대본까지** / **장면까지** |
| AI 영상 비중 | 기본 0.15 (샷의 15%만 AI 영상). **올리면 비용이 많이 올라갑니다** |
| 찾을 소재 수 | 기본 5건 |
| 쓸 대본 수 | 점수 높은 순. 기본 1편 |
| 영상 길이 | 기본 4분 |
| 분야 | 비우면 알아서 섞습니다 |

**처음에는 "테스트만"으로 돌려보세요.** 돈이 한 푼도 들지 않고, 코드가 제대로
돌아가는지만 확인합니다. 초록 체크가 뜨면 준비가 된 겁니다.

## 결과 보기

실행이 끝나면 그 실행 화면 맨 아래 **Artifacts** 에 `ai-surprise-숫자` 가
생깁니다. 다운로드하면 안에:

- `inbox/` — 찾아온 소재 (JSON 파일 하나당 소재 하나)
- `content/001/script.md` — 대본
- `content/001/scenes.json` — 장면 (사람이 읽고 판단하는 것)
- `content/001/prompts.json` — 화면 프롬프트 (Phase 3이 기계로 읽는 것)
- `logs/` — 실행 기록

화면에는 소재가 카드로 나옵니다.

```
┌─ 1. 죽은 남자가 5년 뒤 호텔을 예약했다 ⭐추천
│  (요약)
│
│  점수: 92/100   위험도: 5/100   사실성: CONFIRMED
│  관문: 통과
│  출처 2개:
│    · [PRIMARY] A신문 https://...
└─
```

**관문**이 세 가지입니다.

| 관문 | 뜻 |
|---|---|
| 통과 | 바로 대본을 씁니다 |
| 검토 필요 | 대본을 쓰지 않습니다. 출처를 직접 열어보고 판단해 주세요 |
| 다룰 수 없음 | 저장조차 하지 않고 버립니다 |

> **유튜브에 아무것도 올라가지 않습니다.** Phase 1에는 업로드 코드가 아예
> 없습니다. 결과는 파일로만 나옵니다.

# ⚙️ 어려운 방법 — PC에서 직접 (개발할 때만)

코드를 고치면서 돌려볼 때 쓰는 방법입니다. 평소에는 위의 버튼 방식을 쓰세요.

<details>
<summary>펼쳐보기</summary>

### 준비

`ai-surprise` 폴더에 `.env` 파일을 만들고 한 줄을 넣습니다.

```
ANTHROPIC_API_KEY=sk-ant-여기에키
```

그다음 설치합니다.

```
cd ai-surprise
npm install
```

> `.env`는 `.gitignore`에 들어 있어 GitHub에 올라가지 않습니다.
> 로그에도 찍히지 않게 코드에서 막아뒀습니다.

### 명령

```
npm test                              테스트 (API 키 없이 · 돈 안 듦 · 몇 초)
npm run collect                       소재 찾기
npm run list                           보관함 보기
node src/main.mjs script <파일명>      그 소재로 대본 쓰기
node src/main.mjs auto --scripts=1     소재 찾기부터 대본까지 한 번에
node src/main.mjs auto --scripts=1 --scenes   장면·프롬프트까지 이어서
node src/main.mjs scenes --id=001      그 편의 장면·프롬프트 만들기
node src/main.mjs scenes --id=001 --dry-run   쪼개기만 (비용 0원)
```

개수와 분야를 정할 수 있습니다.

```
node src/main.mjs collect --count=3
node src/main.mjs collect --category="과학적 미스터리"
```

**'검토 필요' 소재는 그냥 진행되지 않습니다.** 출처를 직접 확인하고
괜찮다고 판단하셨으면 `--force` 를 붙입니다.

```
node src/main.mjs script 파일명.json --force
```

## 이 시스템이 지키는 것

### 1. 가짜 이야기를 사실처럼 방송하지 않는다

인터넷에 도는 "실화 미스터리" 상당수는 출처를 따라가면 원전이 없습니다.
그래서 두 겹으로 막습니다.

- **1차 기록이 없는 소재는 아예 버립니다.** 당대 신문, 판결문, 공문서,
  학술자료가 1차 기록입니다. 커뮤니티 글이나 요약 블로그만 있으면 버립니다.
- **출처가 2개 미만이면 점수가 100점이어도 자동 진행하지 않습니다.**
  이 규칙은 AI 판단에 맡기지 않고 코드로 못박았습니다. AI는 재미있는
  이야기를 앞에 두면 출처가 부족해도 통과시키려는 쪽으로 기웁니다.

### 2. 사실과 재현을 대본에서 구분한다

대본의 모든 문단에 태그가 붙습니다.

| 태그 | 뜻 |
|---|---|
| `[FACT]` | 1차 기록으로 확인되는 내용 |
| `[RECONSTRUCTION]` | 기록을 바탕으로 장면을 재현한 것 |
| `[THEORY]` | 가설이나 가능성 |
| `[UNKNOWN]` | 현재 확인되지 않은 부분 |

태그 없는 문단이 하나라도 있으면 대본이 `SCRIPT_READY`로 올라가지 않습니다.

### 3. 유튜브 수익화 기준을 실제로 통과한다

유튜브는 2025년 7월에 '반복 콘텐츠' 정책을 **'비정품 콘텐츠'** 로 바꾸면서,
*"일반적이거나 독창성 없는 템플릿으로 만든 AI 콘텐츠로, 제작자의 원본 통찰이나
관점을 더하지 않고 대량 생산된 느낌을 주는 것"* 을 수익화 대상에서 제외했습니다.
2026년 7월에는 *"기존 포맷을 서로 바꿔 쓸 수 있을 정도로 모방한 콘텐츠"* 도
목록에 들어갔습니다.

AI를 썼다는 이유만으로 막히지는 않습니다. 막히는 건 **템플릿 양산물**입니다.
그래서 대본 구조에 **`[OUR_READING]` "우리가 주목한 것"** 섹션을 고정으로 넣었습니다.
이 섹션이 빠진 대본은 검증에서 걸립니다.

> 100편을 만든 뒤에 추가하면 앞의 100편이 전부 템플릿 양산물로 남습니다.
> 그래서 Phase 1부터 넣었습니다.

### 4. 보는 사람이 불편한 화면을 만들지 않는다

미스터리 소재는 실종·사망·범죄가 자주 나옵니다. 그대로 두면 AI는 시체, 피,
상처, 공포 영화식 연출을 그립니다. 그러면 두 가지가 동시에 일어납니다.

- 시청자가 불쾌해서 바로 나갑니다. 이 채널은 이야기를 보여주는 채널이고
  충격을 보여주는 채널이 아닙니다 (기획서 22번).
- 유튜브가 2026년 7월에 **"충격을 노린 불쾌한 콘텐츠"** 를 수익화 제외 목록에
  명시로 넣었습니다. 영상이 남아도 돈이 안 벌립니다.

그래서 금지 목록을 화면 설계 지시에 넣고, **돌아온 프롬프트를 코드로 다시
검사합니다.** `blood`, `corpse`, `wound`, `zombie` 같은 말이 들어 있으면
한 번 다시 설계시키고, 두 번 다 걸리면 사람이 보도록 멈춥니다.

긴장은 **"보여주지 않음"** 으로 만듭니다. 이게 이 채널의 방식입니다.

> 아무도 없는 복도 · 반쯤 열린 문 · 치우지 않은 식탁 · 멈춘 시계 ·
> 꺼진 전등 · 빈 의자 · 바닥에 떨어진 열쇠

시체를 보여주는 것보다 이게 더 무섭고, 아무도 불쾌하지 않습니다.

그리고 **실존 인물은 사실적으로 그리지 않습니다.** 얼굴이 보이는 샷은
코드가 무조건 이미지로 고정합니다 — AI 영상으로 실존 인물이 움직이는 장면을
만드는 건 유튜브 합성 콘텐츠 정책에서 가장 민감한 영역이고 명예훼손 위험도
가장 큽니다. 비용 문제가 아니라 안전 문제라 예산보다 먼저 적용합니다.

### 5. 승인한 대본과 영상에서 읽히는 말이 같다

장면을 쪼개는 일은 **AI가 아니라 코드가** 합니다.

AI에게 "대본을 장면으로 쪼개서 돌려줘"라고 하면 쪼개면서 나레이션을 요약하거나
문장을 다듬습니다. 그러면 사람이 승인한 대본과 영상에서 실제로 읽히는 말이
달라지고, 승인 절차가 무의미해집니다.

그래서 코드가 글자를 한 자도 바꾸지 않고 쪼갭니다. 그리고 **쪼갠 뒤에 지문을
다시 찍어서 원문과 같은지 기계로 확인합니다.** 다르면 버그로 보고 멈춥니다.

AI는 "이 장면에 어떤 그림이 어울리나"만 설계합니다.

### 6. AI가 비용을 정하지 못한다

한 편 비용의 70% 이상이 AI 영상 생성에서 납니다. 그런데 AI에게 "이 샷은
영상이 필요한가?"를 물으면 "움직임이 있으면 더 좋다"는 쪽으로 기웁니다.

그래서 역할을 나눴습니다.

| 누가 | 무엇을 |
|---|---|
| AI | "이 샷은 움직임이 얼마나 필요한가"를 0~10점으로 **의견만** 냅니다 |
| 코드 | 예산 안에서 점수 높은 순으로 영상을 **배정합니다** |

이러면 AI가 무엇을 하든 편당 영상 비용의 상한이 보장됩니다. 비중은 숫자
하나(`VIDEO_SHOT_RATIO`)로 조절합니다. 기본 0.15, 절대 상한은 12클립입니다.

AI 영상 생성이 실패하면 이미지 + 카메라 움직임으로 대체합니다(기획서 9번).
그래서 영상 샷에도 이미지 프롬프트와 카메라 움직임을 함께 남겨둡니다.

### 7. 사람 승인 없이 넘어가지 않는다

기획서 18번대로 세 군데에서 멈춥니다.

1. **소재 승인** — '검토 필요' 소재는 `--force` 없이 진행되지 않습니다
2. **대본 승인** — 대본이 나오면 멈춥니다. 다음 Phase는 사람이 시작합니다
3. **최종 영상 승인** — Phase 7에서 들어갑니다

## 비용

편당 비용은 영상 생성(Phase 3)이 대부분을 차지합니다. Phase 1은
대본·심사만이라 작습니다.

실행이 끝나면 쓴 토큰이 화면에 나옵니다. 실제 금액은
https://console.anthropic.com/settings/usage 에서 확인하세요.

**"테스트만"으로 돌리면 돈이 한 푼도 들지 않습니다.** AI를 한 번도 부르지 않습니다.

비용을 줄이려면 단계별로 모델을 내릴 수 있습니다. GitHub에서 쓸 때는
리포 Settings → Secrets and variables → Actions → **Variables** 탭에,
PC에서 쓸 때는 `.env`에 넣습니다.

```
CLAUDE_MODEL_COLLECT=claude-sonnet-5-5
CLAUDE_MODEL_SCORE=claude-haiku-4-5
CLAUDE_MODEL_SCRIPT=claude-sonnet-5-5
```

> 지금 워크플로는 이 값들을 읽지 않습니다. 필요해지면 `ai-surprise.yml`의
> `실행` 단계에 `env:` 로 넘기면 됩니다.

기본값은 전부 `claude-opus-5-5` 입니다. 기획서 22번이 "영상 품질보다
소재와 이야기가 우선"이라고 했고, 그 소재와 이야기를 만드는 게 이 단계라서
품질 쪽에 기본값을 뒀습니다.

어느 쪽이 나은지는 실제로 돌려서 글을 비교해 보고 정하는 게 맞습니다.

- **업로드는 비공개(PRIVATE)가 기본값**이고, AI 표시(`status.containsSyntheticMedia`)를

## 알려진 문제

### 기획서 2번과 3번의 점수 항목이 서로 맞지 않습니다

- 기획서 2번 필드: `interesting_score`, `mystery_score`, `visual_score`, `story_score`
- 기획서 3번 배점: 신기함 25 / 반전 25 / 사실성 20 / 영상화 15 / 제목 15

2번에는 '사실성'과 '제목'에 해당하는 필드가 없고, 3번에는 `story_score`에
해당하는 항목이 없습니다.

**3번의 배점을 정답으로 보고 필드를 맞췄습니다.** `mystery_score`는
`twist_score`(반전), `story_score`는 `title_score`(제목)로 바꿨고
`fact_score`를 새로 넣었습니다. 합계가 정확히 100점이 됩니다.

다르게 가고 싶으면 `src/model.mjs`의 `SCORE_WEIGHTS` 한 곳만 고치면
프롬프트·스키마·검증이 같이 따라갑니다.

### 나레이션 속도가 추정치입니다

대본 분량과 장면 길이를 "분당 330자"(공백 제외)로 계산하고 있습니다.
실제 TTS로 읽혀보고 보정해야 하는 값입니다. Phase 4에서 측정합니다.

숫자는 `src/narration.mjs` 한 곳에만 있습니다. 거기만 바꾸면 대본 분량
지시와 장면 길이가 함께 따라갑니다. 두 곳에 박아두면 "4분으로 쓴 대본이
장면 합계는 5분"이 되는 식으로 조용히 어긋나고, Phase 5에서 영상과 음성
길이가 안 맞는데 원인을 찾기 어려워집니다.

### 장면 수가 섹션 수보다 적어질 수 없습니다

장면은 섹션 경계를 넘지 않습니다(HOOK 문단과 CASE 문단이 한 장면에 섞이면
이야기의 토막이 뭉개집니다). 대본 섹션이 9개이므로 장면은 최소 9개입니다.

아주 짧은 대본(섹션당 문단 1개)이면 장면이 9개가 되어 기획서 목표인 12~15개를
벗어납니다. 오류로 보지 않고 경고만 합니다 — 짧은 대본은 장면이 적은 게 맞습니다.

### `sports-news/`와 코드가 일부 겹칩니다

`utils/` 세 파일은 `sports-news/`에서 가져왔습니다. 하나로 합치지 않은 이유는
`sports-news`가 매일 돌아가는 도구라서, 이쪽 작업이 그쪽을 깨뜨리지 않게
떼어두려고입니다.

> 참고로 `sports-news/src/ai/client.mjs`에는 시한폭탄이 하나 있습니다.
> 거기서 쓰는 "특정 도구 강제 호출" 방식은 Opus 5.5 / Sonnet 5.5에서
> 400 오류가 납니다. 지금은 Sonnet 5와 Haiku 4.5를 쓰고 있어 괜찮지만,
> 그쪽 모델을 최신으로 올리는 순간 SEO 단계가 깨집니다.
> 이 프로젝트는 처음부터 모델에 따라 갈라지게 만들었습니다
> (`src/ai/client.mjs`의 `canForceTool`).
