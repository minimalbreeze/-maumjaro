# AI 서프라이즈 — 자동 콘텐츠 제작 시스템

실제로 있었던 이상한 이야기를 찾아 심사하고, 유튜브 영상 대본까지 만듭니다.

**지금은 Phase 1입니다.** 소재 수집 · 심사 · 대본까지 됩니다.
장면 분할, 이미지·영상 생성, 나레이션, 편집, 업로드는 아직 없습니다.

---

## 처음 한 번만 — 준비

### 1. API 키 넣기

`ai-surprise` 폴더에 `.env` 라는 파일을 만들고 아래 한 줄을 넣습니다.

```
ANTHROPIC_API_KEY=sk-ant-여기에키
```

키는 https://console.anthropic.com 에서 발급합니다.

> `.env`는 `.gitignore`에 들어 있어 GitHub에 올라가지 않습니다.
> 로그에도 찍히지 않게 코드에서 막아뒀습니다.

### 2. 설치

```
cd ai-surprise
npm install
```

## 쓰는 법

### 소재 모으기

```
npm run collect
```

웹에서 소재를 찾아 심사하고 보관함(`inbox/`)에 넣습니다. 몇 분 걸립니다.

개수나 분야를 정할 수도 있습니다.

```
node src/main.mjs collect --count=3
node src/main.mjs collect --category="과학적 미스터리"
```

### 보관함 보기

```
npm run list
```

소재마다 카드가 나옵니다. 점수, 위험도, 출처, 그리고 **관문 판정**이 보입니다.

| 관문 | 뜻 |
|---|---|
| 통과 | 바로 대본 쓸 수 있습니다 |
| 검토 필요 | 출처를 직접 열어보고 판단해 주세요 |
| 다룰 수 없음 | 저장조차 하지 않고 버립니다 |

### 대본 쓰기

```
node src/main.mjs script 2026-10-04_소재제목.json
```

파일명은 `npm run list` 에 나옵니다.

**'검토 필요' 소재는 그냥 진행되지 않습니다.** 출처를 직접 확인하고
괜찮다고 판단하셨으면 `--force` 를 붙입니다.

```
node src/main.mjs script 파일명.json --force
```

### 테스트

```
npm test
```

API 키 없이, 돈 안 들이고 몇 초 만에 끝납니다. 코드를 고친 뒤에는 꼭 돌려보세요.

## 이 시스템이 지키는 것

### 1. 가짜 이야기를 사실처럼 방송하지 않는다

인터넷에 도는 "실화 미스터리" 상당수는 출처를 따라가면 원전이 없습니다.
그래서 두 겹으로 막습니다.

- **1차 기록이 없는 소재는 아예 버립니다.** 당대 신문, 판결문, 공문서,
  학술자료가 1차 기록입니다. 커뮤니티 글이나 요약 블로그만 있으면 버립니다.
- **출처가 2개 미만이면 점수가 100점이어도 자동 진행하지 않습니다.**
  이 규칙은 AI 판단에 맡기지 않고 코드로 못박았습니다. AI는 재미있는
  이야기를 앞에 두면 출처가 부족해도 통과시키려는 쪽으로 기웁니다.

### 2. 사실과 재현을 대본에서 구분한다

대본의 모든 문단에 태그가 붙습니다.

| 태그 | 뜻 |
|---|---|
| `[FACT]` | 1차 기록으로 확인되는 내용 |
| `[RECONSTRUCTION]` | 기록을 바탕으로 장면을 재현한 것 |
| `[THEORY]` | 가설이나 가능성 |
| `[UNKNOWN]` | 현재 확인되지 않은 부분 |

태그 없는 문단이 하나라도 있으면 대본이 `SCRIPT_READY`로 올라가지 않습니다.

### 3. 유튜브 수익화 기준을 실제로 통과한다

유튜브는 2025년 7월에 '반복 콘텐츠' 정책을 **'비정품 콘텐츠'** 로 바꾸면서,
*"일반적이거나 독창성 없는 템플릿으로 만든 AI 콘텐츠로, 제작자의 원본 통찰이나
관점을 더하지 않고 대량 생산된 느낌을 주는 것"* 을 수익화 대상에서 제외했습니다.
2026년 7월에는 *"기존 포맷을 서로 바꿔 쓸 수 있을 정도로 모방한 콘텐츠"* 도
목록에 들어갔습니다.

AI를 썼다는 이유만으로 막히지는 않습니다. 막히는 건 **템플릿 양산물**입니다.
그래서 대본 구조에 **`[OUR_READING]` "우리가 주목한 것"** 섹션을 고정으로 넣었습니다.
이 섹션이 빠진 대본은 검증에서 걸립니다.

> 100편을 만든 뒤에 추가하면 앞의 100편이 전부 템플릿 양산물로 남습니다.
> 그래서 Phase 1부터 넣었습니다.

### 4. 사람 승인 없이 넘어가지 않는다

기획서 18번대로 세 군데에서 멈춥니다.

1. **소재 승인** — '검토 필요' 소재는 `--force` 없이 진행되지 않습니다
2. **대본 승인** — 대본이 나오면 멈춥니다. 다음 Phase는 사람이 시작합니다
3. **최종 영상 승인** — Phase 7에서 들어갑니다

## 비용

편당 비용은 영상 생성(Phase 3)이 대부분을 차지합니다. Phase 1은
대본·심사만이라 작습니다.

실행이 끝나면 쓴 토큰이 화면에 나옵니다. 실제 금액은
https://console.anthropic.com/settings/usage 에서 확인하세요.

비용을 줄이려면 `.env`에서 단계별로 모델을 내릴 수 있습니다.

```
CLAUDE_MODEL_COLLECT=claude-sonnet-5-5
CLAUDE_MODEL_SCORE=claude-haiku-4-5
CLAUDE_MODEL_SCRIPT=claude-sonnet-5-5
```

기본값은 전부 `claude-opus-5-5` 입니다. 기획서 22번이 "영상 품질보다
소재와 이야기가 우선"이라고 했고, 그 소재와 이야기를 만드는 게 이 단계라서
품질 쪽에 기본값을 뒀습니다.

어느 쪽이 나은지는 실제로 돌려서 글을 비교해 보고 정하는 게 맞습니다.

## 아직 안 한 것 (다음 Phase)

| Phase | 내용 |
|---|---|
| 2 | 장면 자동 분할 + 이미지 프롬프트 |
| 3 | AI 이미지·영상 생성 |
| 4 | AI 나레이션 + 자막 |
| 5 | 자동 영상 편집 (ffmpeg) |
| 6 | 썸네일 + 제목 생성 |
| 7 | YouTube API 업로드 |

Phase 4·5에서 미리 정해둔 것:

- **자막은 한국어 하드섭 1개만** 화면에 굽습니다. 두 언어를 겹치면 글자밭이 됩니다.
- **하드섭 위치는 화면 아래 240px을 비웁니다.** 유튜브가 자기 자막을
  화면 하단에 띄우고, 그 위치는 우리가 제어할 수 없기 때문입니다.
  쇼츠(9:16)는 하단 UI가 더 크니 600px 이상 비웁니다.
  이 숫자들은 추정치라 Phase 5에서 실제로 올려보고 보정해야 합니다.
- **영어는 SRT 트랙으로 따로 올립니다.** 유튜브 자동 번역은 쓰지 않습니다.
  우리는 대본 원문을 갖고 있어서 음성인식으로 되돌릴 이유가 없습니다.
- **나레이션 TTS는 문장별 타임스탬프를 주는 쪽**을 씁니다. 그게 자막 싱크를
  자동으로 맞추는 유일한 방법입니다.
- **업로드는 비공개(PRIVATE)가 기본값**이고, AI 표시(`status.containsSyntheticMedia`)를
  자동으로 켭니다.

## 알려진 문제

### 기획서 2번과 3번의 점수 항목이 서로 맞지 않습니다

- 기획서 2번 필드: `interesting_score`, `mystery_score`, `visual_score`, `story_score`
- 기획서 3번 배점: 신기함 25 / 반전 25 / 사실성 20 / 영상화 15 / 제목 15

2번에는 '사실성'과 '제목'에 해당하는 필드가 없고, 3번에는 `story_score`에
해당하는 항목이 없습니다.

**3번의 배점을 정답으로 보고 필드를 맞췄습니다.** `mystery_score`는
`twist_score`(반전), `story_score`는 `title_score`(제목)로 바꿨고
`fact_score`를 새로 넣었습니다. 합계가 정확히 100점이 됩니다.

다르게 가고 싶으면 `src/model.mjs`의 `SCORE_WEIGHTS` 한 곳만 고치면
프롬프트·스키마·검증이 같이 따라갑니다.

### 나레이션 속도가 추정치입니다

대본 분량을 "분당 330자"로 계산하고 있습니다. 실제 TTS로 읽혀보고
보정해야 하는 값입니다. Phase 4에서 측정합니다.

### `sports-news/`와 코드가 일부 겹칩니다

`utils/` 세 파일은 `sports-news/`에서 가져왔습니다. 하나로 합치지 않은 이유는
`sports-news`가 매일 돌아가는 도구라서, 이쪽 작업이 그쪽을 깨뜨리지 않게
떼어두려고입니다.

> 참고로 `sports-news/src/ai/client.mjs`에는 시한폭탄이 하나 있습니다.
> 거기서 쓰는 "특정 도구 강제 호출" 방식은 Opus 5.5 / Sonnet 5.5에서
> 400 오류가 납니다. 지금은 Sonnet 5와 Haiku 4.5를 쓰고 있어 괜찮지만,
> 그쪽 모델을 최신으로 올리는 순간 SEO 단계가 깨집니다.
> 이 프로젝트는 처음부터 모델에 따라 갈라지게 만들었습니다
> (`src/ai/client.mjs`의 `canForceTool`).
