# 스포츠 뉴스 자동화 — 최상위 원칙

이 문서는 `sports-news/` 안의 모든 작업에 우선한다. 새 기능을 넣거나 글쓰기
규칙을 손볼 때, 아래 다섯 가지와 충돌하면 그 요청 쪽을 다시 확인하고 이 문서를
따른다.

> 리포 루트의 `CLAUDE.md`(맘운자로 브랜드 원칙)는 그대로 유효하다.
> 이 문서는 그 아래에서 스포츠 뉴스 도구에만 적용된다.

## 네 가지 원칙 (운영자가 직접 정한 것)

### 1. AI가 쓴 글처럼 보이지 않는다
사람이 직접 쓴 블로그 글이어야 한다. 판에 박힌 연결어("또한", "결론적으로"),
기계적인 목록 나열, 속 빈 미사여구("귀추가 주목됩니다")를 쓰지 않는다.
읽는 사람이 "이거 AI가 썼네"라고 느끼는 순간 글의 신뢰도가 무너진다.

### 2. 구글 서치콘솔에 색인이 잘 된다

**2026-10-10 에 이 절을 구글 공식 문서에 맞춰 다시 썼다.** 운영자가 구글
"검색엔진 최적화(SEO) 기본 가이드"를 넘겨 줬고, 그 문서의 **'무시해야 할 사항'**
절이 우리가 강제하던 것들을 정면으로 부정하고 있었다. 아래 표가 그 대조다.

| 우리가 강제했던 것 | 구글 문서가 한 말 | 지금 |
|---|---|---|
| 대표 키워드 밀도 **1.25~2.5% 강제** | "같은 단어를 과도하게 반복하면 … **유인 키워드 반복은 Google의 스팸 정책에 위반됩니다**" | **상한만 본다**(2.5%). 하한 없음 |
| 본문 공백 제외 **3,000자 하한** | "**콘텐츠 길이 자체는 순위 결정과 관련 없습니다**" | **권고로만.** 점수에 안 넣는다 |
| H2 계층 | "순서를 바꾸어도 상관없습니다" | 소제목은 **내용을 말해주려고** 쓴다 |
| 중복이 색인 실패 원인 (내가 한 주장) | "중복 콘텐츠는 비효율적이지만, 이로 인해 **직접 조치가 부과되지는 않습니다**" | 색인 실패의 원인으로 보지 않는다 |

그리고 같은 문서가 이렇게 잇는다.

> "**단어를 다르게 작성하면**(반복되지 않도록 자연스럽게 작성) 키워드를 더 많이
> 사용하기 때문에 Google 검색에 표시될 가능성이 더 높습니다."

**반복이 아니라 다양함이다.** 우리 파이프라인은 반대쪽으로 글을 밀고 있었다.

#### 지금 지키는 것

- **구글은 링크로 페이지를 찾는다.** 같은 문서: "Google은 주로 이미 크롤링한
  다른 페이지의 링크를 통해 페이지를 찾습니다. … 사이트맵을 제출할 수도 있지만
  **이것이 필수는 아닙니다.**" 발행 633편 중 구글이 아는 것이 156편뿐이었던
  이유가 여기다 — 사이트맵에는 다 있었지만 **가리키는 링크가 없었다.**
  글끼리 잇는 일은 `internal-links.mjs` 가 한다. **새 글도 반드시 잇는다.**
- 대표 키워드는 **제목·첫 문단·소제목 하나·메타 설명에 한 번씩.** 그걸로 끝이다.
  나머지 자리에서는 **같은 대상을 다른 이름으로 부른다**(정식명칭 → 줄인 이름 →
  종목+성격). 억지로 더 넣지 않는다.
- **키워드는 본문에 그대로 나오는 말**로 잡는다. Rank Math 가 "있는 그대로"
  찾기 때문에 본문에 없는 긴 구절을 잡으면 0회가 된다. 한 번은 나와야 한다.
- 메타 설명이 본문을 정확히 요약한다.
- 슬러그에 대표 키워드가 들어간다.
- 소제목이 그 섹션 내용을 그대로 말해준다 — 계층을 맞추려고가 아니라,
  읽는 사람이 어디에 무엇이 있는지 알게 하려고 쓴다.
- 자주 묻는 질문은 구조화 데이터(JSON-LD)로도 내보낸다.
  **본문에 실제로 적힌 질문과 답만** 넣는다 — 다르면 구글이 스팸으로 본다.
- **분량은 권고다.** 못 채웠으면 길이를 늘릴 생각 대신 ⑤ 배경·원리·비교에
  **쓸 수 있는 것이 남았는지**만 본다. 없으면 그대로 둔다.

#### 왜 이걸 문서에 남기나

운영자가 정해 둔 원칙을 내 판단으로 바꾸면 안 되는 자리였다. 그래서 바꾸기
전에 근거(구글 문서 원문)와 함께 물었고, **2026-10-10 운영자가 "이건 다
적용해줘"로 승인했다.** 다음에 누가 "밀도가 낮다"고 되돌리려 하면 이 표를 본다.

### 2-1. 구글 색인은 더 쫓지 않는다 (2026-11-10 운영자 결정)

> "이제 구글에 집중하지 않는다. 네이버에 집중한다. 네이버 색인만 되어도 많이 들어온다."
> "구글은 이제 사이트에서 알아서 가져가 색인되면 모를까 **별도로 색인 요청을 하지 않는다.**"
> "시간 낭비다. 어차피 안 올려준다. 잘 올려 주는 네이버에 집중하고, 네이버를 통해 수익을 늘린다."

#### 그날 실제로 잰 것

운영자가 서치콘솔에서 **색인 생성됨 0 / 색인 안 됨 660**을 보고 물었다.
막아 둔 것이 있는지 전부 확인했다. 없었다.

| 의심한 것 | 결과 |
|---|---|
| `maumjaro_google_noindex` 깃발 | **0편 / 722편** |
| 메타 설명·대표 키워드가 빈 글 | **0편 / 722편** |
| 사이트맵이 구글에 가는가 | **725개 정상** (post-sitemap 1~4 + page) |
| `name="robots"` 줄 | 애초에 만들지 않는다 |

**우리 쪽 기술 문제가 아니었다.** 남은 설명은 하나뿐이다 — 구글이 읽고 나서
올리지 않기로 고른 것이다. 서치콘솔의 두 줄이 그 말을 한다.

- **발견됨 - 색인 생성되지 않음 434** — 주소는 아는데 **크롤링조차 안 했다**
- **크롤링됨 - 색인 생성되지 않음 226** — 읽고 나서 **안 올리기로 했다**

11/1 에 넣은 유효성 검사가 11/7 에 **실패**로 끝난 것도 같은 말이다. 재검사는
기술 오류를 고쳤을 때 통과하는 절차인데, 고칠 기술 오류가 없었다.

#### 같은 글로 네이버는 자란다

| | 구글 | 네이버 |
|---|---|---|
| 30일 노출 | — | **17.6만** (+1,148%) |
| 30일 클릭 | — | **1.3천** (+521%) |
| 색인 | **0** | 잘 된다 |

**같은 글이다.** 한쪽은 0이고 한쪽은 19배로 늘었다.

#### 그래서 지금부터

1. **구글에 색인 요청을 따로 하지 않는다.** 서치콘솔 유효성 검사도 다시 돌리지
   않는다. 알아서 가져가면 가져가는 것이고, 그걸 기다리느라 시간을 쓰지 않는다.
2. **글감·제목·메타는 네이버 기준으로 고른다.** `config/search-demand.md` 의
   네이버 실측이 기준이고, 구글 서치콘솔 숫자는 판단 근거로 쓰지 않는다.
3. **수익도 네이버 유입으로 본다.** 쿠팡·애드센스 자리를 판단할 때 보는 숫자는
   네이버 클릭이다.
4. ⚠️ **그래도 끊지는 않는다.** 위 ② 절의 색인 규칙(내부 링크, 키워드 자리,
   사이트맵, 구조화 데이터)은 **그대로 지킨다.** 이것들은 네이버에도 똑같이
   쓰이고, 유지 비용이 0 이다. 쫓지 않는 것과 망가뜨리는 것은 다르다.
5. ⚠️ **`name="robots"` 금지는 그대로다.** 구글을 포기한다고 해서 전체
   noindex 를 쓸 이유가 생기는 것이 아니다 — 그건 네이버까지 끊는다.

### 3. 다른 AI가 인용하기 좋다

**글 쓰는 순서는 `config/writing-playbook.md` 에 있다**(2026-10-18 운영자가
여러 AI에게 물어 모은 자료 여덟 개를 정리한 것이다). 우리가 가장 약한 곳은
**독자적인 정보**·**본문에 출처 밝히기**·**실사 이미지**·**저자 정보** 넷이고,
그 문서 5절과 8절이 각각 무엇을 누가 할 수 있는지 가른다.

못 박아 둘 것: **어떤 글쓰기 방식도 AI 인용을 보장하지 않는다.** 운영자가
준 자료도 OpenAI 공식 안내를 인용해 그 점을 반복한다. 우리는 가능성을
높일 뿐이고, 글에 "AI가 인용한다"고 쓰지 않는다.

- 글 맨 앞 핵심 요약이 답 그 자체가 되게 쓴다.
- 문장을 떼어 읽어도 뜻이 통하게 쓴다. "그는", "이 대회는" 같은 대명사로
  문장을 시작하지 않고 이름과 날짜를 문장 안에 그대로 쓴다.
- "지난주", "내년"처럼 읽는 시점에 따라 달라지는 말 대신 고정된 날짜를 쓴다.
- 자주 묻는 질문은 첫 문장에서 곧바로 답한다.

### 4. 블로그 검색에 걸리는 제목
- 사람들이 실제로 검색할 고유명사(선수명·대회명)를 **제목 맨 앞**에 둔다.
- 이모지를 키워드보다 앞에 두지 않는다.
- "이슈", "화제" 같은 뭉뚱그린 말 대신 구체적인 숫자·이름·일정을 넣는다.
- 낚시는 쓰지 않는다. 제목이 약속한 내용이 본문에 있어야 한다.

## 다섯째 원칙: 적게 쓰고 잘 쓴다 (2026-10-08 운영자 지시)

> "항상 비용을 최소한으로 쓰고 최고의 퀄리티의 글을 작성하는 것을 중요시해줘"

위 네 가지와 같은 자리에 둔다. 둘 중 하나를 포기하는 선택지는 없다. 싸게
하려고 품질을 깎지 않고, 잘 쓰려고 돈을 함부로 쓰지 않는다. **둘이 부딪히면
"글을 두 번 쓰지 않는 것"으로 푼다** — 한 번에 제대로 나오는 글이 제일 싸다.

구체적인 단가·절약 방법·품질 기준은 아래 '비용' 절에 실측값으로 적어 두었다.
새 기능을 넣을 때 그 절의 숫자가 바뀌면 그 절도 같이 고친다.

## 독자가 실제로 찾는 것

`config/search-demand.md`에 네이버 서치어드바이저 실측치가 있다. 추측으로
글감을 고르지 않는다. 요약하면 둘이다.

> 글감을 **어떻게 좁힐지**는 `config/writing-playbook.md` 3절에 있다
> (2026-10-18 운영자 자료 여덟 개). 아래 실측과 그 자료가 같은 말을 한다 — 좁은
> 질문은 살고 넓은 소식은 죽는다. 중계·일정 글 357편이 전부 죽어 있는
> 것이 그 증거다.

1. **대회명 + 상금** — 유입 1위. "어스몬다민컵우승상금" 134클릭, CTR 18.7%
2. **시설명 + 이용방법/예약/복장/가격/가는 길** — CTR 10~25%

대회 결과·개장 소식 같은 뉴스성 검색어는 TOP 30에 거의 없다. 점수표
(`news/rank.mjs`의 `실전_유입`)가 이 순서대로 가점을 준다.

새 데이터가 들어오면 `config/search-demand.md`를 고치고 점수표도 함께 손본다.

### 같은 종목만 연달아 쓰지 않는다

점수표는 실측이라 틀리지 않았다. 그런데 그 결과로 매일 같은 종목이 1위가 됐다.
파크골프장 개장 기사에는 '개장'·'가는 길'·'이용료'·'예약방법'이 자연히 다 들어가
구조적으로 상위를 먹는다. 실제로 7264·7268·7272 세 편이 연달아 파크골프였다.

그래서 **점수표는 그대로 두고**, 최근 글(발행+임시글 6편)의 카테고리에만 감점을
준다(`news/variety.mjs`). 한 편 썼으면 -8, 두 편 -18, 세 편 이상 -30이고 직전
글과 같으면 -6을 더 깎는다. 실측 점수차가 2~3점으로 촘촘해서 이 정도면 종목이
자연히 돌아간다.

임시글도 센다 — 임시글로 쌓아두고 나중에 발행하는 흐름이라 발행된 것만 보면
방금 만든 같은 종목 임시글이 안 보인다.

끄려면 `VARIETY_PENALTY=off`. 조회가 실패하면 감점 없이 그냥 간다 — 다양성
때문에 글을 못 쓰게 되면 안 된다.

### 대표 키워드는 "고유명사 + 돈·숫자·방법"으로 잡는다

2026-10-04에 실측으로 확인했다.

| 키워드 | 월 검색량 | 성격 |
|---|---|---|
| 신지애 우승 상금 | 40 | 상시 |
| 신지애 우승 횟수 | 40 | 상시 |
| 신지애 누적상금 | 80 (두 표기 합) | 상시 |
| 남서울cc 파3 | 90 (경쟁 LOW) | 상시 |
| **신지애 일본여자오픈** | **검색량 잡히지 않음** | 며칠 |

**대회명+결과는 검색량이 없다.** 사람은 "선수명+상금", "시설명+시설종류"로 찾는다.
`ai/seo.mjs`의 focusKeyword 지시에 이 규칙이 박혀 있다.

조사가 붙은 말은 키워드가 아니다("신지애가"). 글 7769에서 자동 교체가 조사 붙은
구절을 집어 SEO 점수가 66점으로 떨어졌다. `seo/rankmath.mjs`의 `조사앞까지()`가 막는다.

### 분량은 권고다. 그래도 한 군데서만 센다

**분량으로 글을 되돌리지 않는다**(2026-10-10, 위 ② 절 참고). `checkRankMath` 는
글자 수를 **보여만 주고** 점수에 넣지 않고(`정보: true`), `lintArticle` 은
`issues` 가 아니라 `notes` 에 적는다. ⑤ 섹션 보완(돈이 드는 재호출)도 분량으로는
돌지 않는다.

그래도 **세는 기준은 한 군데로 맞춰 둔다.** 지시서는 "공백 포함", 채점표는
"공백 제외"로 재던 탓에 지시를 지킨 글이 떨어진 적이 있다(글 7769: 공백 포함
3,651자 → 공백 제외 2,782자). 지금도 지시서 권고는 4,000자(공백 포함), 채점표
표시는 3,000자(공백 제외)로 같은 곳을 가리킨다. **한쪽을 바꿀 때는 다른 쪽도
같이 바꾼다.**

### 영구히 남는 기록에 가점한다

통산 N승·그랜드슬램·영구시드·최초·누적상금은 색인이 붙은 뒤에도, 내년에도
검색된다. 우승 자체는 매주 나오므로 가점하지 않는다. `news/rank.mjs`의
`오래사는_기록`이 이걸 본다. 넣기 전에는 신지애의 통산 30승·사상 첫 그랜드슬램
글감이 후보 48개 중 상위 12개에 들지 못했다.

### 우리 목적은 유입이 아니라 수익이다

사람이 들어오고 → 광고를 누르고 → 수익이 쌓인다. 지금은 적어도 되지만 미래에는
커야 한다. 점수표를 손볼 때 "검색이 오래 되는가"만 보지 않는다. **오래 검색되는
글과 돈이 되는 글은 다르다.**

- 선수 기록·계보 글(통산 30승, 그랜드슬램)은 수명이 길다. 하지만 읽고 나간다.
- 시설 이용·용품·예약 글은 **돈을 쓸 준비가 된 사람**이 들어온다. 광고가 답이 된다.

한때 이걸 점수표 가점(`구매의도`)으로 넣었다가 **2026-10-05에 운영자 지시로
걷어냈다.** 두 가지 이유가 있었다.

1. 가점의 근거가 실측이 아니라 추정이었다. 실제 수익 데이터가 없는 상태에서
   "용품 +24"가 맞는 숫자인지 증명할 수 없었다.
2. 한 글자 패턴(채·화·공·볼)이 사람 이름과 지명을 먹었다. "김채영"의 채,
   "화성시"의 화. 돈 되는 글을 올리려던 가점이 거꾸로 엉뚱한 글을 1등으로
   밀어 올렸다.

**교훈은 남긴다.** 한국어 점수표에 한 글자 패턴을 쓰지 않는다 — 한 글자는
어디에나 들어 있다. 그리고 실측 없이 가중치를 만들지 않는다. 실제 수익 데이터는
`config/revenue.md`에 모으며 아직 비어 있다. 그 숫자가 들어오면 그때 근거를
가지고 다시 설계한다.

광고 자리나 종류를 바꿀 때는 **측정할 수 있는 상태를 먼저 만든다.** 측정 없이
옮기면 좋아졌는지 나빠졌는지 알 수 없다 — 카테고리별 쿠팡 링크가 그래서
되돌려졌다.

### 계절성은 아직 못 본다

남서울 파3는 4~5월·9~10월이 피크고 12~1월엔 1/8로 떨어진다(실측). 지금 쓰는 글이
어느 계절 수요인지 코드는 모른다. 구글 트렌드·네이버 데이터랩 접근이 없어서다.
**지어낸 숫자로 메우지 않는다.** 붙일 수 있게 되면 `demand.mjs`만 고치면 된다.

## 글의 흐름 (몇 달 뒤에도 검색되게)

운영자가 정한 여섯 단계다. 한 편의 글은 이 순서로 간다.

| 단계 | 하는 일 | 코드가 지키는 자리 |
|---|---|---|
| ① 관심은 오르고 경쟁은 덜한 글감 | 상승 신호 + 경쟁 밀도로 고른다 | `news/demand.mjs` |
| ② 사람이 궁금해할 제목 | 제목 괄호 안을 질문으로 | 지시서 제목 규칙 + `seo/flow.mjs` |
| ③ 첫 문장에서 답변 | 인사말 없이 결론부터 | 지시서 ① 핵심 요약 |
| ④ 데이터·사례 | 구체적인 숫자와 비교 대상 | 지시서 ④ 기록과 데이터 |
| ⑤ 오래 검색될 개념으로 확장 | 규칙·원리·역사·비교 | 지시서 ⑤ 배경·원리·비교 |
| ⑥ 다음 검색을 유도하는 끝맺음 | 다음에 궁금해질 것을 이름으로 | 지시서 ⑩ + `seo/flow.mjs` |

**뉴스는 사람을 데려오는 입구일 뿐이다.** 글을 살아 있게 만드는 것은 ④와 ⑤다.
속보를 받아쓰면 한 주 뒤에 죽는다.

### 색인보다 빨리 죽는 글감은 쓰지 않는다

구글 색인은 보통 3~14일 걸린다. 그런데 "3R 유해란 단독 선두"는 하루면 끝난
이야기다. **색인이 되어 검색결과에 뜨기 시작할 무렵엔 이미 대회가 끝나 있어서
그 말을 찾는 사람이 없다.** 방문자가 생기기 시작할 시점에 글이 이미 죽어 있다.

실제로 글 7685가 그렇게 나왔고 운영자가 바로 짚었다. 점수표에 그 감점이
없었던 탓이다 — '속보'·'하이라이트'는 걸러내는데 대회 중간 상황은 안 걸러졌고,
오히려 '메이저'·'우승 경쟁' 같은 말로 가점을 받았다.

`news/rank.mjs`의 `색인전_소멸`이 이걸 막는다.

| 걸리는 것 | 감점 |
|---|---|
| 3R·중간 순위·리더보드 | -20 |
| 단독 선두·공동 선두·추격전 | -18 |
| 9회말·전반전·연장 승부 | -18 |
| 오늘 경기·이번 주 경기 | -12 |

**대회 자체는 막지 않는다.** 일정·중계·출전명단·상금은 대회 내내 검색된다.
막는 것은 "지금 이 순간의 중간 상황"뿐이다. 같은 대회라도 각도에 따라 점수가
100점쯤 갈린다(실측: 중간 순위 -36점 vs 일정·중계·상금 66점).

### 진행 중인 경기로 글을 하나 더 만들지 않는다 (2026-11-05 운영자 지시)

> "그거까지 따로 쓰지는 말자. 그러면 블로그가 아니라, 거의 뉴스 기사 수준이
> 되어 버리니"

2026 한국시리즈가 1승 1패로 진행 중일 때 내가 **"한국시리즈 글을 따로 쓸까"**를
꺼냈고, 운영자가 접었다. 위의 `색인전_소멸` 과 **겹치지만 같지는 않다.**

| | 막는 이유 |
|---|---|
| `색인전_소멸` | 색인이 붙을 때쯤 **검색하는 사람이 없어서** |
| 이 항목 | 그렇게 쌓으면 **블로그가 아니라 뉴스 사이트가 되어서** |

둘째가 더 넓다. 중계·일정 각도라 점수가 높게 나오는 글이어도, **지금 벌어지는
경기 하나를 위해 글을 새로 만드는 것**이면 걸린다. 점수표가 통과시켜도 이쪽이
먼저다.

**그럼 어떻게 하나 — 이미 있는 글을 고친다.** 같은 날 한국시리즈 내용은 글을
새로 쓰지 않고 KBO 허브(5762)의 중계 절을 고치는 것으로 끝냈다. 허브는 가을마다
다시 검색되고, 뉴스는 사흘이면 죽는다.

### 새 글이냐 허브 업데이트냐 — 종목으로 가른다 (2026-11-05 운영자 지시)

> "프로야구는 인기 스포츠니 구단별로 작성하지만 다른 스포츠는 해당 내용을
> 토대로 허브 글에다가 일정 등을 추가로 고쳐서 업데이트해보자, 제목에도
> 반영을 하고, **그래야 꾸준히 검색이 될 것 같아**"

| | 어떻게 |
|---|---|
| **프로야구** | 인기 종목이다. **구단별로 글을 새로 쓴다**(10개 구단) |
| **그 밖의 종목** | 새 글을 만들지 않고 **허브에 절을 끼우고 제목에 반영한다** |

바로 위 항목과 같은 생각이다. 다른 점은 **무엇을 기준으로 가르는가**뿐이다 —
위는 "진행 중인 경기냐", 여기는 "인기 종목이냐".

**왜 제목까지 고치나.** 절만 끼우면 그 말로 검색해 들어올 길이 없다. 사람들이
치는 말이 제목 앞에 와야 한다(위 ④ 제목 규칙). 그래서 허브를 키울 때는
**절 + 제목**이 한 묶음이다. 슬러그는 건드리지 않는다 — 주소가 바뀌면 색인이
끊긴다.

실제로 그날 둘을 그렇게 했다.

| 글 | 받은 검색어 | 한 일 |
|---|---|---|
| 11637 당구 허브 | PBA일정·PBA팀리그·PBA팀리그일정·PBA대진표 | 팀리그 일정 절을 끼우고 제목 앞을 `PBA 팀리그 일정·대진표` 로 |
| 5762 KBO 허브 | — | 중계 절을 고치고 2027 시즌 안내를 더함 |

**프로야구 구단 글은 하나를 먼저 재고 간다.** 운영자가 "이번 글이 효과가 있으면
인기순으로 더 작성하자"고 했다. 11866(기아 타이거즈)이 그 첫 글이다. 열 편을
한꺼번에 쓰지 않는다 — 재방문 실험에서 배운 것과 같다(루트 지시서).

**허브에 넣을 것은 오래 사는 것만 고른다.** 순위표·중간 전적은 넣지 않는다.
라운드가 끝나면 틀린 숫자가 된다. 대신 **어디서 보는지**를 적는다. PBA 팀리그
절에서 순위를 빼고 공식 순위 페이지로 보낸 것이 그 예이고, 왜 안 적었는지를
본문에도 밝혔다.

①에 대해 정직하게 밝혀둘 것: 우리는 구글 트렌드나 네이버 데이터랩에 접근하지
못한다. 그래서 "검색량"을 직접 알 수 없고, 이미 긁어온 기사 목록에서 계산할 수
있는 대리 신호(최근 24시간 기사 쏠림 + 매체 수)를 쓴다. 지어낸 숫자보다 낫다.
트렌드 API를 붙일 수 있게 되면 `demand.mjs`만 고치면 된다.

## 이 원칙들을 코드가 지키는 방법

원칙을 문서로만 두면 지켜지지 않는다. 검사할 수 있는 것은 검사한다.

| 원칙 | 코드가 지키는 자리 |
|---|---|
| ① AI 티 | `lintArticle()` — AI 상투어 금지·남용 검사 |
| ② 색인 | `checkRankMath()` — 키워드 위치·**반복 상한**·소제목 · `faqSchemaBlock()` · **`internal-links.mjs` — 글끼리 링크(구글이 페이지를 찾는 경로)** |
| ③ AI 인용 | `config/style-warp.md`의 핵심 요약·자주 묻는 질문 규칙 |
| ④ 제목 | `config/style-warp.md`의 제목 규칙, `checkRankMath()`의 제목 키워드 검사 |
| 여섯 단계 흐름 | `checkFlow()` — 실행할 때마다 점수와 빠진 단계를 찍는다 |

글투를 바꾸고 싶으면 `config/style-warp.md`만 고친다. 코드는 건드릴 필요 없다.

## 중계 배너는 허브로 보낸다 (2026-11-02 운영자 지시)

> "이제 앞으로 중계 배너는 허브로 진행한다. 없으면 중계 허브를 만들어
> 진행한다. 다만 내가 강제한 배너는 강제로 넣는다."

세 줄이 전부다. 순서대로 지킨다.

### 1. 기본은 허브다

대회별·단발 중계 글의 버튼은 **바깥 채널이 아니라 내 블로그의 중계 안내 글**로
보낸다. 바깥으로 보내면 독자가 거기서 또 헤매고, 중계권이 바뀌면 글마다 고쳐야
한다. 허브 하나만 고치면 되는 쪽이 싸다.

| | 어디로 |
|---|---|
| 대회별·단발 글 | **내 블로그 안내 글** |
| 안내 글 자신 | **바깥 공식 채널** (`허브일때`) |

`add-watch.mjs` 가 글의 공개 주소와 설정의 주소를 견줘 안내 글 자신을 알아보고,
`허브일때` 가 있으면 그 바깥 링크로 바꿔 단다. 없으면 아무것도 넣지 않는다 —
자기 자신으로 가는 버튼은 눌러도 같은 자리다.

### 2. 허브가 없으면 만든다

종목에 안내 글이 없으면 **먼저 만들고** 배너를 건다. 설정이 가리키는 주소에 글이
없으면 독자를 404 로 보낸다. 설정 파일이 스스로 적어 둔 원칙 그대로다 —
**"없는 링크를 배너로 거는 것은 독자를 속이는 일"**.

실제로 그 순서를 지켰다(2026-11-02). 설정이 `k리그-중계`·`epl-중계`·`mlb-중계`
를 가리키게 해 둔 뒤 **배너를 걸기 전에 그 셋을 먼저 썼다.**

2026-11-02 기준 안내 글 여덟 개: `안세영-중계`(배드민턴) · `여자농구-중계` ·
`프로농구-중계` · `nba-중계` · `wtt-중계`(탁구) · `k리그-중계` · `epl-중계` ·
`mlb-중계`, 그리고 먼저 있던 `2026-kbo-프로야구`.
아직 없는 종목: **당구·볼링·바둑·골프·배구** (주소는 설정에 다 있다).

### 3. 운영자가 못박은 배너가 가장 세다

`config/watch-links.json` 의 **`byPost`** 에 글 번호를 키로 적으면, 카테고리·
match·허브 판정을 **전부 건너뛰고** 그것을 쓴다. 자기 자신을 가리켜도 그대로
넣는다.

```json
"byPost": { "2922": { "primary": { "text": "...", "url": "..." } } }
```

**코드가 고른 것보다 사람이 고른 것이 앞선다.** 그 글에만 해당하는 사정은 코드가
알 수 없고, 지정한 사람은 알고 지정한 것이다. 이 칸이 비어 있으면 평소대로
1·2번으로 간다.

## 글 안의 링크

- **링크는 현재 창에서 연다.** `target="_blank"`를 쓰지 않는다. 새 창으로 띄우면
  독자가 원래 글로 돌아오는 길을 잃고, 모바일에서는 탭이 쌓여 성가시다.
- target이 없으면 `rel="noopener"`도 필요 없다. 그건 새 창을 띄울 때만 쓰는 것이다.
- 바깥 사이트로 나가는 링크에는 `rel="nofollow"`를 남긴다.
- 예외: 쿠팡 파트너스 광고는 제휴사가 준 코드를 그대로 쓴다(`config/ad-coupang.html`).
  우리가 손대면 광고가 동작하지 않을 수 있다.

## 비용 — 적게 쓰고 잘 쓴다 (운영자가 정한 원칙)

**싸게 쓰는 것과 잘 쓰는 것은 둘 다 지킨다.** 둘이 부딪히면 "글을 두 번 쓰지
않는 것"으로 푼다 — 한 번에 제대로 나오는 글이 제일 싸다.

### 매체가 적은 종목은 뉴스 경로가 구조적으로 막힌다

같은 날 바둑에서 확인했다. 수집 3건이 다 들어왔는데 **"같은 사건을 2곳 이상이
다뤄야 한다"**는 조건에 묶음 2개가 전부 걸러졌다. 바둑·당구처럼 보도 매체가
적은 종목은 이 벽을 잘 못 넘는다.

→ 이런 종목은 **처음부터 `--research`(공식 자료 조사)나 `--article`** 로 간다.
뉴스 경로로 먼저 찔러보면 5원씩 버린다.

### 재료가 눈앞에 있으면 반드시 넘겨라 (2026-10-09, 412원 날림)

란커배 글에서 두 번 연달아 실패했다.

| 시도 | 결과 | 비용 |
|---|---|---|
| 뉴스 수집 (subject 오염) | 글감 없음 | 5원 |
| 공식 자료 조사 | 확인된 사실 **0건** / 미확인 7건 → 작성 거부 | **407원** |

두 번째가 뼈아프다. 사실 확인 단계가 웹검색 9회(참조 45건)를 다 쓰고도
상금·규칙·역대 우승자를 **1차 출처로 하나도 확정하지 못했다.** 입력 토큰
125,331 — 지금까지 실측 중 가장 비싼 축인데 결과물이 없다.

**그런데 그 재료는 이미 눈앞에 있었다.** 각도를 정하려고 돌린 웹검색에서
경향신문 기사 두 건(상금 180만 위안, 덤 7집반, 제한시간, 48강 대진)이
나왔었다. 그 본문을 `--article` 로 넘겼으면 1차 출처를 손에 쥔 채로
시작했을 것이다.

**규칙: 각도를 정하려고 검색을 했고 거기서 쓸 만한 기사를 봤다면, 그 기사
본문을 `--article` 로 넘긴 뒤에 돌린다.** 본문을 받을 수 없으면(컨테이너
네트워크 차단 등) 운영자에게 붙여 달라고 하고 기다린다. 맨손으로 돌려서
모델이 검색 한도를 태우게 두지 않는다.

`--research` 는 "웹에 공식 자료가 있을 때" 쓰는 모드지, "재료 없이도
알아서 해준다"는 모드가 아니다.

### 돈 쓰기 전에 0원으로 먼저 본다

| 0원 모드 | 언제 |
|---|---|
| 오늘의 글감 후보 보기 | 글감을 고르기 전에 항상 |
| 글 찾기 / 중계·앱·공식 배너 상태 보기 | 이미 있는 글을 건드리기 전에 |
| 배너 넣기 (미리보기) | 적용 전에 무엇이 바뀌는지 확인 |

**글감 선택이 비용을 정한다.** 점수표가 높아도 웹에 자료가 없는 글감(지역
대회 등)은 확인된 사실이 모자라 짧고 나쁜 글이 나온다 — 7793 이 그랬다
(확인된 사실 5건 / 미확인 8건 → SEO 72점). 돈은 돈대로 쓰고 글은 못 쓴다.

### 운영자가 기사를 주면 싸진다

`--article` 로 기사를 받으면 검색 의존이 줄어 입력 토큰이 크게 떨어진다
(83,940 → 25,822, 실측). 재료가 손에 있는 글감은 이 경로로 쓴다.

### 품질 기준 — 이 선을 넘긴 글만 쓸 만하다

| 항목 | 기준 | 못 넘기면 |
|---|---|---|
| 흐름(`checkFlow`) | **100점** | ⑤ 가 빠지면 한 주 뒤에 죽는다 |
| SEO(`checkRankMath`) | **84점 이상** | 메타 설명·키워드 자리는 손으로 1분이면 고친다. 분량은 점수에 없다 |
| 확인된 사실 | 미확인보다 많을 것 | 적으면 글감을 바꾸는 게 맞다 |

7797·7801 이 흐름 100점으로 나온 첫 글들이다. 이게 기본값이어야 한다.

### 모델과 손잡이

| 단계 | 모델 | 왜 |
|---|---|---|
| 사실 확인 | `claude-sonnet-5` | 웹검색이 붙어 **가장 비싸다** |
| 본문 작성 | `claude-sonnet-5` | Opus 면 3배쯤 든다 |
| SEO·분류 | `claude-haiku-4-5` | 다 쓴 글에서 뽑는 단순 작업 |

Opus 5와 Sonnet 5로 각각 뽑아 비교했을 때 **양식 준수와 사실 처리는 차이가
없었다.** 달라지는 건 문장의 결 정도다. 그래서 기본을 Sonnet 으로 둔다.
특정 글만 공들이고 싶으면 `CLAUDE_MODEL_WRITE=claude-opus-5` 로 돌린다.

- `WEB_SEARCH_MAX_USES` (기본 4) — 낮추면 싸지지만 사실 확인이 부실해진다.
  3으로 내렸을 때 "검색 도구 제한으로 추가 검증이 불가능하다"며 글을 못 쓴
  적이 있다. **아껴봐야 글이 안 나오면 그게 제일 비싸다.**
- `WRITE_EFFORT` (기본 medium) · `VERIFY_EFFORT` — 생각 토큰이 출력 요금이다.
- `VERIFY_MAX_TOKENS` (기본 24000) — 낮추면 결과가 잘려 호출값을 통째로 버린다.

들어간다** — 빼먹지 말고 함께 밝힌다. 숫자를 좋게 보이려고 반올림하지 않는다.

## PR 은 내가 머지한다 (2026-10-10 운영자 지시)

> "이제 머지도 니가 그냥 자동으로 하면 안되는 건가 번거롭다"

**된다. 앞으로 내가 머지한다.** 운영자에게 "머지해 주세요"라고 넘기지 않는다.
한 사람이 쓰는 리포이고, 리뷰어가 따로 없고, 머지를 기다리는 동안 다음 작업이
전부 멈춘다. 흐름은 이렇다.

1. 브랜치에 커밋 → 푸시 → **draft PR** 을 연다(설명에 무엇을 왜 바꿨는지 남긴다)
2. 전체 테스트 통과를 확인한다
3. **draft 를 내리고 내가 머지한다** — 기록은 PR 설명으로 남으므로 잃는 것이 없다
4. 실제로 사이트를 건드리는 모드는 그다음에 돌린다

**그래도 묻는 경우는 있다.**
- 되돌릴 수 없는 것(글 삭제, 발행, 도메인·광고 설정)
- wiki 밖을 건드릴 수밖에 없는 변경
- 운영자가 정한 원칙(이 문서·루트 지시서) 자체를 바꾸는 것 —
  근거를 들고 먼저 묻는다. 밀도·분량 하한이 그랬다

머지가 빨라진 만큼 **미리보기를 건너뛰지는 않는다.** 본문이나 제목을 수백 편
한꺼번에 고치는 모드는 여전히 미리보기를 먼저 돌린다. 머지는 코드를 올리는
일이고, 적용은 사이트를 바꾸는 일이다. 둘은 다르다.

## 좋아지는 일은 묻지 않고 한다 (2026-10-18 운영자 지시)

> "페이드캠 글은 알아서 연결하고, **긍정적인 것들은 안 물어 보고 진행하면 된다**"

미리보기가 깨끗하면 **적용까지 내가 한다.** "적용할까요?"로 멈추지 않는다.
글끼리 링크를 걸어 둘지 묻느라 하루를 보내면, 그 하루 동안 새 글은 구글이
찾지 못하는 외딴 섬으로 남는다. 기다리는 비용이 실수하는 비용보다 클 때가 있다.

**묻지 않고 하는 것** — 0원이고, 되돌릴 수 있고, 효과가 분명한 일.
글끼리 링크, 오타·잘린 문장 고치기, 메타 설명 채우기, 배너 넣기,
쿠팡 위치 옮기기 같은 것들이다. 미리보기 결과는 **보고는 한다** — 묻지
않는 것이지 숨기는 것이 아니다.

**여전히 묻는 것** — 위의 세 가지에 하나를 더한 넷이다.
- 되돌릴 수 없는 것(글 삭제, 발행, 도메인·광고 설정)
- wiki 밖을 건드릴 수밖에 없는 변경
- 운영자가 정한 원칙 자체를 바꾸는 것
- **돈이 드는 것** (글당 190~370원. "적게 쓰고 잘 쓴다"가 운영자 원칙이다)

미리보기에서 **예상과 다른 것이 나오면** 그때는 묻는다. 0편이 잡히거나,
바뀌는 글 수가 뜻밖으로 크거나, 표 밖의 것이 바뀐다는 경고가 뜨면
그대로 밀지 않는다. 묻지 않아도 되는 것은 **확인이 끝난 일**이지
확인을 건너뛴 일이 아니다.

## 허락은 그때의 사실 위에서 받은 것이다 (2026-11-03)

**되돌릴 수 없는 작업은 허락받은 시점의 상태를 다시 확인하고 실행한다.**

2026-11-03 에 서교림 글(11802)을 두고 운영자에게 **"발행 전 임시글이니
지우고 다시 올리면 깨끗하다"**고 보고했고 "지우고 다시 올려라"를 받았다.
삭제 미리보기를 돌려 보니 **`publish`** 였다 — 그 사이에 운영자가 발행했다.
**내 보고가 그 순간에는 맞았고, 실행할 때는 틀렸다.**

지웠으면 주소(`서교림-4관왕`)가 끊기고, 워드프레스가 슬러그를 붙잡아

2. 상태가 보고한 때와 다르면 **멈추고 다시 말한다.** 허락은 백지수표가

  content="noindex">` 를 쓰면 **모든 검색엔진에게** 하는 말이라 네이버 유입까지

  없으면 네이버가 무엇을 따르든 영향이 없다.
  - Rank Math 의 `rank_math_robots` 칸은 `name="robots"` 를 만든다. 쓰지 않는다.

    못했다. **확인 못 한 것에 기대는 설계를 하지 않는다.**
- 워드프레스에는 **임시글(draft)로만** 저장한다. 자동 발행하지 않는다.
- API 키·비밀번호는 화면과 로그 어디에도 남기지 않는다.
- 뉴스 원문을 복사하거나 문장을 바꿔 쓰지 않는다. 확인된 사실을 재료로 새로 쓴다.
- 확인되지 않은 것을 사실처럼 쓰지 않는다. **이 원칙이 분량과 점수보다 위에 있다.**

## 광고 정책은 어떤 경우에도 어기지 않는다 (2026-11-10 운영자 지시)

> "위반은 절대 안 된다. 꼭! 지켜라"

**수익보다 위에 둔다.** 광고를 하나 더 넣어서 버는 돈보다, 정책을 어겨 계정이
막히거나 수익이 무효 처리되는 쪽이 훨씬 비싸다. 돈이 걸린 영역이라 "이 정도면
괜찮겠지"로 넘기지 않는다 — 로또 글에서 당첨을 암시하지 않는 것과 같은 선이다.

### 지키는 것 넷

1. **실수로 누르게 만들지 않는다.** 닫기 버튼·내비게이션·본문 링크 자리에서
   광고가 열리면 안 된다. 그 클릭은 독자가 원해서 누른 것이 아니다.
   애드센스 광고 게재위치 정책이 막는 바로 그 경우다.
2. **광고를 콘텐츠처럼 보이게 하지 않는다.** 광고와 본문 사이에 여백을 두고,
   제휴 고지를 **광고보다 앞에, 읽히는 크기로** 붙인다.
3. **화면을 가로막지 않는다.** 전면 팝업(인터스티셜)은 쓰지 않는다. 하단 고정
   바는 본문 아래 여백을 그만큼 주어 **마지막 줄을 덮지 않게** 한다.
4. **다른 광고를 덮지 않는다.** 애드센스는 광고가 가려지는 것을 허용하지
   않는다. 쿠팡 바가 애드센스와 겹치면 **우리 바를 숨긴다**(겹침확인).

### 2026-11-10 에 실제로 고친 것 둘

| 무엇이 잘못됐나 | 어떻게 고쳤나 |
|---|---|
| 닫기 버튼 아래 절반이 쿠팡 캐러셀에 덮여, **누르면 광고가 열렸다** | 버튼을 바 바깥 위로 완전히 뺐다(`top:-40px`·높이 36px → 아래끝 -4px). 겹치는 픽셀이 0 이라 쌓임 순서와 무관하다 |
| 하단 바 고지문이 **10px·`#888`** (흰 바탕 명암비 **3.54**) 이고 광고 **뒤**에 있었다 | **12px·`#555`**(명암비 **7.46**)로 키우고 **광고 앞**으로 옮겼다 |

첫째는 운영자가 "처음 누르면 광고로 넘어가고 돌아와 다시 누르면 닫힌다"고
짚어 준 증상이다. 우리 사이트가 그 상태였다.

### 검사로 막아 뒀다 (`test/add-sticky.mjs`)

- 닫기 버튼의 `top + height <= 0` — 광고 영역과 겹치면 떨어진다
- 솟은 높이를 **본문 여백과 겹침 검사가 함께** 쓰는가
- 고지문이 **광고보다 앞**에 있는가 · **12px 이상**인가 · **명암비 4.5 이상**인가

눈대중으로 "작게 넣어 두자"가 되는 순간 깨지는 자리라 숫자로 박았다.

⚠️ **본문 블록(`config/ad-coupang.html`)은 제휴사가 준 코드라 건드리지 않는다.**
그쪽 고지문은 스타일이 없어 본문 글자색을 그대로 물려받는다. 하단 바에서 작아진
것은 **우리가 감싸며 줄인 것**이라 우리가 고칠 자리였다.

⚠️ **앱 안에는 광고를 넣지 않는다**(루트 지시서). 이 절은 wiki 블로그 이야기다.

## 발행 전에 고유명사를 기사와 글자 단위로 맞춰 본다 (2026-10-22 운영자 승인)

위 "확인되지 않은 것을 사실처럼 쓰지 않는다"를 **실제로 지키는 절차**다.
원칙만 적어 두면 지켜지지 않는다는 것을 이틀 연속으로 확인했다.

### 실제로 당한 일 두 번

| 날짜 | 글 | 재료에 적힌 것 | 글에 나간 것 |
|---|---|---|---|
| 10-21 | 10711 우상혁 | **김주는**(고양특례시청) | **김주은** — 흔한 이름 쪽으로 바뀜 |
| 10-22 | 10721 쇼트트랙 | 판매처 **언급 없음** | "**외국인은 티켓링크, 내국인은 네이버 예약**" |

둘 다 **발행된 뒤에** 발견했다. 10711 은 1차 출처(뉴시스·경기일보·인천일보)에
분명히 적힌 이름을 모델이 바꿨고, 10721 은 기사에 아예 없는 구분을 웹검색에서
끌어와 채워 넣었다.

### 왜 기존 검사로는 안 잡히나

사실 확인 단계와 `checkRankMath` 는 **숫자와 형식**을 본다. 사람 이름이
한 글자 다른 것, "누가 어디서 사는지"가 바뀐 것은 **어느 검사에도 걸리지
않는다.** 문법도 맞고 그럴듯하기 때문이다.

그리고 이런 값은 **독자가 바로 행동하는 정보**다. 틀린 예매처를 믿고
엉뚱한 사이트에서 헤매는 것이 분량 미달보다 훨씬 나쁘다.

### 그래서 발행 전에 이것만 맞춰 본다

**운영자가 재료를 준 글은, 발행 전에 아래 네 가지를 기사와 글자 단위로
대조한다.** 0원이고 몇 분이면 된다.

1. **사람·팀 이름** — 선수, 소속, 감독. 한 글자도 다르면 안 된다.
2. **판매처·중계처** — 티켓링크/네이버 예약/방송사. 재료에 없으면 **쓰지 않는다.**
3. **주소와 날짜** — 경기장 이름, 개최일, 판매 시작 시각.
4. **돈** — 상금, 입장권 가격.

**재료에 없는데 글에 있는 것**은 전부 의심한다. 웹검색이 가져온 것일 수
있고(그래서 맞을 수도 있다), 지어낸 것일 수도 있다. 맞는지 확인되기 전에는
빼거나, 확인된 범위까지만 남긴다 — 10721 에서 "티켓링크와 네이버 예약에서
구매할 수 있다"로 줄인 것이 그 예다.

### 이미 발행된 글에서 찾으면

`typo-fix` 표에 글 번호를 박아 고친다. 같은 문장이 본문과 구조화
데이터(JSON-LD) 양쪽에 있으면 **문자열 치환이라 한 항목으로 둘 다 바뀐다** —
그게 맞다. 둘이 달라지면 구글이 스팸으로 본다. 다만 구조화 데이터는 JSON 이라
**치환할 내용에 HTML 태그를 넣지 않는다.**

## 도구 입력에 한글을 손으로 적지 않는다 (2026-11-09, 여덟 번 당하고 적는다)

워크플로를 돌릴 때 `mode`·`title`·`post_ids` 같은 입력에 한글을 적으면
**글자가 깨져서 들어간다.** 하루에 여덟 번 났다.

| 적으려 한 것 | 들어간 것 |
|---|---|
| 문로그알안 · 횡인 · 5전 · 켠팝 | (원문을 알아볼 수 없게 뒤섞임) |
| 김민솔 · 3관왕 | 김민솜 · 3관웕 |
| 16살 · 신지애 · 함께 · 제쳐 | 16씵 · 신지에 · 함깘 · 제쳬 |
| 평균타수 · 놓쳐 · 챔피언십 | 평금타수 · 놓쫌 · 추피언십 |
| 누를 수 없는 · 글 전체 | 눌를 수 없는 · 글 전율 |

**그중 둘이 '실제 적용' 모드였다.** 발행된 글 제목이 깨진 글자로 바뀔
상황이었고 run 을 취소해서 막았다(`cancelled` 확인). 막은 것은 눈이었고
**눈은 매번 안 걸린다.**

### 두 가지 길로 푼다

**1. 글 내용(제목·설명·본문)은 파일에 쓴다.** `제목초안/*.json`·`섹션초안/*.md`
를 만들고 워크플로에 **파일 경로만** 넘긴다. 파일에 쓴 한글은 오늘 한 번도
깨지지 않았다(절 초안 일곱 개, 검사 넷, 커밋 메시지 전부 멀쩡하다).

⚠️ 그 길의 첫 실전이 **조용히 실패**했다 — 단계 `env:` 에 `IN_FILE` 을 안
넣어 파일 분기가 통째로 건너뛰어졌고, 가드도 그 안에 있어 같이 건너뛰어져
"바뀔 내용이 없습니다" 로 **성공처럼** 끝났다. 셸은 없는 변수를 빈 문자열로
준다. 검사(`run` 블록의 `IN_*` 가 그 단계 `env` 에 다 있는가)로 막아 뒀다.

**2. `mode` 는 choice 라 파일로 못 넘긴다. API 를 직접 부른다.**
워크플로 파일에서 그 줄을 **그대로 떠서** 보낸다. 셸에서 만든 한글은
안 깨진다.

```bash
# ⚠️ 줄 번호로 집지 않는다 — 모드를 하나 더하면 번호가 밀린다.
#    모드 이름의 **알아볼 수 있는 조각**으로 찾고, 하나만 걸리는지 세어 본다.
# ⚠️ bash 는 한글 변수명을 못 쓴다(`조각=...` 은 command not found 다).
# ⚠️ **줄 시작(`- '`)에 조각을 붙이지 않는다.** 모드 이름의 앞부분을 모르면
#    안 걸린다. 2026-11-09 에 `- '적힌 주소를 링크로` 로 찾았는데 실제 이름이
#    `글자로만 적힌 주소를 링크로` 라서 **0건**이 나왔고, 빈 mode 가 넘어가
#    워크플로가 **기본값인 글쓰기 모드**로 떨어졌다. 311원이 샜다.
#    따옴표 줄만 먼저 거르고, 조각은 **그 안에서** 찾는다.
PIECE='누를 수 없는 주소 세기'
M=$(grep -F -- "- '" .github/workflows/sports-news.yml | grep -F -- "$PIECE" | sed "s/^ *- *'//; s/'$//")
# ⚠️ **빈 값이면 반드시 멈춘다.** 빈 mode 를 보내면 기본값(돈 드는 글쓰기)으로 간다.
[ -n "$M" ] || { echo "그런 모드가 없습니다: $PIECE"; exit 1; }
[ "$(printf '%s' "$M" | grep -c '')" = 1 ] || { echo "조각이 여러 줄에 걸립니다 — 더 길게 적으세요"; exit 1; }
python3 -c "import json,sys; print(json.dumps({'ref':'main','inputs':{'mode':sys.argv[1]}}, ensure_ascii=False))" "$M" > /tmp/body.json
curl -sS -w '%{http_code}\n' -X POST \
  "https://api.github.com/repos/minimalbreeze/-maumjaro/actions/workflows/sports-news.yml/dispatches" \
  -H "Accept: application/vnd.github+json" -H "Content-Type: application/json" \
  --data-binary @/tmp/body.json
```

204 가 오면 큐에 들어간 것이다. 프록시가 토큰을 붙여 주므로 키를 적을
자리가 없다 — 화면과 로그에 비밀이 남지 않는다.

**번호만 넘기는 입력(`post_ids`)은 안전하다.** 숫자와 `전체`·`all` 은
깨질 글자가 없다.
