# 집 하나를 만들 때 반드시 하는 것

배운 것을 집마다 다시 생각하지 않으려고 적어 둔다. **한 집을 시작할 때
이 파일을 열고, 끝낼 때 다시 훑는다.** 2026-11-21 효성님: "지금까지 한
작업들은 나머지 작업에 전부 반영한다."

각 항목 옆에 **왜** 가 붙어 있다. 이유를 모르면 다음 사람이 뺀다.

## 1. 그림

- [ ] **한눈에 보이는 것 하나**를 넣는다 — 트리·연등·큰 창·불빛
      *왜: 검색 결과에서 썸네일은 가로 210px 다. 그냥 예쁜 방은 그 크기에서
      다른 플레이리스트 채널과 구분이 안 된다. 14집이 그렇게 됐다*
- [ ] **LP 턴테이블**과 **큰 통유리창**을 반드시 넣는다 (`art/그림규칙.md`)
- [ ] **아래 가운데를 비운다** — 자막 띠·이퀄라이저·로고 자리
- [ ] 받은 뒤 **LP 재킷·간판·액자를 잘라서 확대**하고 글자가 있는지 본다
      *왜: 11집 재킷에 HOLIDAY JAZZ 가 박혀 있었다. 축소판에서는 안 보인다*
      ```
      ffmpeg -i art/0NN-*.png -vf "crop=420:300:0:560,scale=840:600" /tmp/crop.png
      ```
- [ ] 글자가 있으면 **구도는 그대로 두고 글자만 지워 다시 뽑는다**
      (같은 그림을 imageReferences 로 주고 "글자를 지워 달라")

## 2. 곡

- [ ] 받은 뒤 **제목을 한 줄씩 읽는다.** 화면 한가운데 박히는 글자다
      - 파일명 같은 것 (`okey` · `2-Saha1` · `#02 (Gullinburste-2018)`)
      - 전부 대문자 (`WET`)
      - 주제와 반대 (`The Factory` · `Gloomy wanderer` · `Call of nature`)
      - 그림과 어긋나는 것 (한옥 그림에 `Japan`)
- [ ] 아티스트 이름도 본다 (`zero-project` 는 파일명처럼 읽힌다)
- [ ] 다른 집과 겹치는지 본다 (`usedElsewhere` 가 보지만 눈으로 한 번 더)
- [ ] **첫 곡을 고른다** — 11집부터의 규칙
      ```
      node playlist/scripts/intro.mjs --vol 0NN
      ```
      *왜: 유입의 69% 가 추천이고 추천은 지속 시간으로 돈다. 인트로 유지율이
      집마다 2.5배 차이났다(1집 50% · 6집 38% · 2집 20%). 10집까지는
      fetch 순서가 그대로 1번이었다 — 아무도 안 골랐다*
      거르개는 **서서히 차오르는 곡만** 찾아낸다. 고르는 것은 사람이 한다.
- [ ] 순서에 뜻을 넣는다 — 무엇으로 열고 무엇으로 닫는가

## 3. 렌더

```
node playlist/scripts/build.mjs --vol 0NN          # 보통
node playlist/scripts/build.mjs --vol 0NN --rain   # 빗소리 (9집)
```
- [ ] 자막 띠 밝기와 막 세기를 확인한다. 막이 0.45 를 넘으면 그림이 너무 밝다
- [ ] ⚠️ 워커가 재시작되면 렌더가 죽는다. mp4 길이를 재서 끝까지 갔는지 본다

## 4. 썸네일·설명란

```
node playlist/scripts/thumbnail.mjs --vol 0NN --at 40
node playlist/scripts/thumbnail.mjs --vol 0NN --bare      # A/B 테스트용
node playlist/scripts/description.mjs --vol 0NN \
  --lead '<검색어> · <두 번째 검색어>' \
  --intro '<장면 한 줄>' \
  --tags '#...' > playlist/out/설명란-0NN.txt
```
- [ ] **`--lead` 를 반드시 준다.** 길이는 자동으로 붙는다
      *왜: 검색 결과에 보이는 것은 설명란 첫 두 줄이다. 7집은 외부 유입이
      Google Search 100% 였는데 그 자리가 비어 있었다*
- [ ] **집마다 검색어를 다르게 한다**
      *왜: 1집과 2집이 둘 다 "작업할 때 듣는 음악" 이면 검색 결과에서
      서로를 밀어낸다. 같은 채널 영상끼리 경쟁시키지 않는다*

## 5. 올릴 때

- [ ] **제목: 검색어를 맨 앞에, "플레이리스트" 를 넣는다**
      *왜: 8집만 검색어를 앞세웠고 검색 유입 23.8% 였다(다른 집 2~8%).
      7집만 제목에 "플레이리스트" 가 있었고 7집만 플레이리스트 이웃을 얻었다*
- [ ] 썸네일 **수동 업로드** (자동 추출 프레임 쓰지 않는다)
- [ ] **재생목록에 추가** — 빠뜨리면 그 집이 연쇄에서 떨어진다
- [ ] **끝화면** 세 개: 재생목록 · 시청자에게 맞는 동영상 · 구독
      **화면 위쪽에 배치한다** (아래는 우리 자막 띠가 있다)
      두 번째 영상부터는 "가져오기" 로 10초면 된다
- [ ] **고정 댓글** — 아래 양식
- [ ] 태그 칸 채우기 (해시태그와 별개다)
- [ ] 아동용 아님 · 쇼츠 리믹스 허용 · 동영상 언어는 비워 둔다

## 6. 언제 올리나

**주제가 날짜를 타면 전날 저녁 8~10시에 올린다.** 유튜브가 색인하는 데
반나절 걸린다.

*왜: 11/18 에 올린 7집(연말 파티)이 첫날 14회였다. 11월에 "연말 파티" 를
검색하는 사람이 없다. 같은 주 6집(공부)은 353회다. 주제가 아니라 날짜의
문제였다.*

`발행계획.md` 의 "앞으로 걸어 둘 날짜" 를 본다.

## 첫 곡 (2026-11-23 효성님 지시 — 어기지 말 것)

**무겁거나 쳐지는 곡으로 시작하지 않는다.** 첫 곡은 듣기 편하거나, 달달하거나,
상큼해야 한다. 수면집도 예외가 아니다 — 처음 30초에 사람이 남을지 나갈지가
갈린다. 드론(한 음이 길게 깔리는 앰비언트), 단조의 엄숙한 성가, 서서히
차오르는 곡은 첫 곡으로 쓰지 않는다.

실제로 어긴 적:
- 18집 첫 곡을 Rendezvous With Rama(Stellardrone, 6:13 우주 앰비언트)로
  골랐다. "수면집에는 느리게 시작하는 긴 곡이 맞다"고 판단했는데 틀렸다.
  2026-11-23 에 다시 렌더했다.
- 11집 첫 곡 O Come O Come Emmanuel 은 단조 성가라 무겁다. 이미 발행해서
  못 고친다(조회 104회를 날릴 수 없다).

`intro.mjs` 는 **서서히 차오르는 곡만** 걸러낸다. 무거운지 밝은지는 못 잰다 —
그건 곡 제목과 장르를 보고 사람이 판단해야 한다.

## 우리 채널 음악의 성격 (2026-11-23 효성님 정리)

전부 **로파이(lo-fi)나 잔잔한 재즈**다. 어느 카페에서 나올 법한 음악이고,
**달달하고 밝은 쪽**이 많다. 무겁고 실험적인 쪽으로 새지 않는다.
무드를 새로 고를 때 이 기준을 먼저 본다.

## 긴 버전(4시간)은 주장 없는 집만 붙인다 (2026-11-23)

효성님 지시 — "이의제기에 문제가 되는 곡이 있는 영상은 영상을 4시간으로
편집할 때 수정한다."

긴 버전은 **새로 올리는 영상**이라, 어느 집을 넣을지 고르는 순간이
주장을 피할 수 있는 유일한 기회다. 이미 발행한 집은 못 고치지만
긴 버전은 고를 수 있다.

**규칙:** `long.mjs --vols` 에 넣을 집은 `저작권주장.md` 를 먼저 보고
**주장 0건인 집**에서만 고른다.

- 2026-11-23 기준 주장 0건: **005 · 006 · 008 · 017**
- 4시간-공부를 006+008+005+017 로 짰다(3:59:31, 66곡, 주장 0건).
  원래 007 을 넣었는데 주장 2건이라 017 로 바꿨다.

주장 0건인 집이 모자라면 **긴 버전을 미룬다.** 주장 붙은 집을 억지로 넣지
않는다 — 캐럴 4시간이 그래서 대기 중이다(011 은 조회 104회로 맨 앞에
와야 하는데 주장 3건, 004·010·007 도 전부 주장이 있다. 019 가 나오면 짠다).

⚠️ 주장을 피하려고 **소리를 덧씌우지 않는다.** 그건 권리 관리 시스템을
피해 가는 짓이다. 우리에겐 정당한 CC BY 라이선스가 있어서 그럴 필요가 없고,
제대로 된 대응은 수익화 직전의 이의 제기다(`저작권주장.md` 의 "대응 순서").

## 앞으로는 4시간짜리 하나만 만든다 (2026-11-27)

효성님 지시 — "앞으로는 4시간짜리로만 만든다. 그런데 분량과 시간이 길다."

지금까지는 **집 네 개를 각각 만들고 → 이어 붙여 4시간**을 만들었다.
20~23집이 그 방식이었는데, 한 편 내는 데 드는 일이 이렇다.

| 단계 | 집마다 | 4집이면 |
|---|---|---|
| 음원 받고 추리기 | 1회 | 4회 |
| 그림 뽑기(생성·1920 내보내기·글자 확인) | 1회 | **4회** |
| 렌더 | 30~40분 | **2시간+** |
| 썸네일·설명란·업로드 시트 | 1벌 | **4벌** |
| 효성님 업로드 | 1번 | **5번**(집 4 + 합본 1) |

**바꾼 방식 — 한 집에 다 담는다.**

긴 영상용 집은 **하나의 폴더에 60곡쯤을 여러 무드에서 받아** 넣고,
그 집 하나를 4시간으로 렌더한다. `long.mjs` 로 이어 붙이지 않는다.

```
node playlist/scripts/fetch-music.mjs --cc --mood 로파이힙합 --vol 024 --n 34
node playlist/scripts/fetch-music.mjs --cc --mood 소울그루브 --vol 024 --n 34
node playlist/scripts/fetch-music.mjs --cc --mood 다운템포   --vol 024 --n 34
   → 추려서 60곡 전후 · 3시간 50분~4시간
node playlist/scripts/build.mjs --vol 024
```

이렇게 하면 **그림 1장 · 렌더 1번 · 글 1벌 · 업로드 1번**이다.
일이 넷에서 하나로 준다.

**잃는 것과 지키는 것**

- 잃는 것: 화면이 4시간 내내 한 장이다. 집을 이어 붙이면 집마다 그림이
  바뀌었다. 다만 이 장르(로파이·틀어두는 음악)의 큰 채널들은 대부분
  정지 화면 한 장이라, 손해는 크지 않다고 본다.
- 잃는 것: 영상 수가 준다. 집 넷 + 합본 다섯 편이 한 편이 된다.
  추천을 받을 창구가 줄어든다. **이건 실제 비용이다.**
- 지키는 것: 첫 곡 규칙 · 한 아티스트 3곡 제한 · 밝기 기준 ·
  LP 체인 · 그림 고정 요소 · CC BY 출처 표기. 전부 그대로다.

**곡 순서는 더 중요해진다.** 4시간을 한 흐름으로 짜야 한다 —
밝게 열고(첫 곡 규칙), 가운데를 두텁게, 뒤로 갈수록 조용하게.
집 단위로 끊기지 않으니 아티스트도 흩어 놓는다(같은 사람 곡이
붙어 나오지 않게).

**20~23집은 이미 만들어 놓았다.** 버리지 않고 이어 붙여 4시간
한 편으로 낸다. 네 집을 따로 올리지는 않는다 — 같은 음악이 두 번
올라가면 서로 조회수를 깎는다.

## 첫머리 음량은 렌더된 영상으로만 잰다 (2026-11-28)

시청 지속 시간이 1회당 4분밖에 안 되는 이유를 찾다가 **집마다 첫 곡의
시작 음량을 원본 mp3 로 재 봤다.** 19집 Jingle Bells 가 첫 10초 -40.3dB,
9집 Drakkar 가 -31.8dB 로 나왔다. "재생을 눌렀는데 소리가 안 난다" 고
판단했는데, **틀렸다.**

**build.mjs 가 곡마다 `loudnorm=I=-16` 을 건다.** 단일 패스 loudnorm 은
동적으로 작동해서 조용한 도입부를 끌어올린다. 렌더된 영상 28편을 다시
재 보니 이렇게 달랐다.

| | 원본 mp3 첫 10초 | 렌더된 영상 첫 10초 | 원본 차이 | 렌더 차이 |
|---|---|---|---|---|
| 019 Jingle Bells | -40.3 | **-22.4** | +24.8 | **+5.9** |
| 009 Drakkar | -31.8 | **-17.6** | +22.5 | **+3.0** |
| 021 Some soft n mellow | -25.4 | **-17.6** | +8.2 | **+1.2** |

**원본으로 잰 값은 시청자가 듣는 것과 다르다.** 앞으로 첫머리를 볼 때는
반드시 렌더된 영상을 잰다.

```
node playlist/scripts/intro.mjs --vol 020 --rendered
```

렌더된 영상 28편의 실측에서 멀쩡한 집은 **0~10초가 -16 ~ -19dB,
본문과의 차이가 ±2dB 안**이었다. 19집만 -22.4dB · +5.9dB 로 혼자
떨어져 있다. 그래서 기준을 **-20.5dB 이상 · 차이 4dB 이하**로 잡았다.

**지금 이 기준에 걸리는 것은 19집과, 19집으로 시작하는 캐럴 긴 버전
둘뿐이다.** 셋 다 이미 발행해서 고치지 않는다(발행한 집은 다시 고치지
않는다). 18집·20집·그루브 4시간은 전부 통과했다.

⚠️ `intro.mjs` 의 원본 기준 거르개는 그대로 둔다. 후보를 추리는 1차
체로는 쓸모가 있다. 다만 **그것만 보고 끝내지 않는다** — 집을 뽑은
뒤 `--rendered` 로 한 번 더 본다.

## 한 편을 내는 규칙 — 2026-11-28 정리

효성님 지시로 바뀐 것들을 한자리에 모은다. **새 영상을 만들 때 이 순서대로 한다.**

### 1. 음원
- 긴 영상 하나에 다 담는다. 집 넷을 따로 만들어 붙이지 않는다.
- 목표의 **두 배 넘게** 받는다. 그루브 쪽 통과율이 44% 였다.
- `--mood` 를 여러 개 돌려 한 폴더(`bgm/0NN/`)에 모은다.
- 한 아티스트 3곡 제한, 첫 곡 규칙(밝게 시작)은 그대로.

### 2. 그림
- 고정 요소 그대로 — LP 턴테이블 · 통유리 커튼월 · 사람 없음 · 밝은 장면 ·
  아래 가운데 여백 · 현대 일본 애니 배경화.
- **받으면 확대해서 글자를 찾는다.** LP 재킷 · 책등 · 액자 · 명판 자리.
- ⚠️ **썸네일은 이미 발행한 어느 영상과도 같으면 안 된다.**
  2026-11-28 에 그루브 4시간 썸네일을 20집과 같은 그림으로 올렸다가
  목록에서 두 개가 똑같아 보였다. 긴 영상은 **아직 안 쓴 그림**으로 쓴다.

### 3. 첫머리 검사
```
node playlist/scripts/intro.mjs --vol <이름> --rendered
```
통과(0~10초 -20.5dB 이상 · 차이 4dB 이하)해야 올린다.

### 4. 설명란과 고정 댓글
```
node playlist/scripts/desc2.mjs --vol <이름> --lang ko --head <머리글> --tags "..." --pin "줄1|줄2|..."
node playlist/scripts/desc2.mjs --vol <이름> --lang en --head <머리글> --tags "..."
```
- **설명란** = 머리글 + 챕터 + 라이선스 안내. 한도 5,000자.
- **고정 댓글** = 짧은 글 + 구독 요청 + **음원 출처 전체**. 한도 10,000자.
  출처를 설명란에서 뺀 것은 길이 때문이고, **지운 게 아니라 옮긴 것**이다.
  CC BY 는 출처 표기가 라이선스 조건이고, 이걸 어기면 수익화 때
  Content ID 주장을 풀 근거가 사라진다.
- 변경 사실 표기(LP 질감을 입혔다)를 반드시 넣는다. CC BY 조건이다.

### 5. 영어판
- **제목과 설명만** 번역한다. 스튜디오 › 자막 › 언어 추가 › 제목 및 설명.
- ⚠️ **영어 고정 댓글은 만들지 않는다**(2026-11-28 효성님). 고정 댓글은
  하나뿐이고 한국어판 하나로 충분하다. 출처는 곡 제목·아티스트·URL 이라
  어느 언어로 봐도 읽힌다.
- 영어 제목은 직역하지 않는다. 그 장르의 실제 검색어를 앞에 둔다 —
  `lofi hip hop radio` · `beats to study and work to` · `music to focus`.

### 6. 기존 영상에 출처를 붙일 때
새 댓글을 만들지 않는다. **기존 고정 댓글을 수정해서 맨 아래에 붙인다.**
고정은 하나만 되고, 고정이 풀린 글은 묻힌다 — 거기에 구독 요청이 있다.
